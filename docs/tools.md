# Tool reference

The blitz.cloud MCP server has 195 tools, grouped below. The server's own list on the [AI tools](https://beta.blitz.cloud/ai) page is always current; this page explains the arguments.

Wherever a tool takes `app`, you can pass the app's name, its address label (`blog` in `blog.lena.prod.page`) or its id. If two apps share a name, the server asks for the id instead of guessing. Databases work the same way with their name or id.

The **Needs** column is the lowest role that may call the tool: `read` for anything that only looks, `deploy` for changing apps, and the owner or manage permissions for billing, domains and members. A call above the connection's role is refused with a sentence saying why.

Tools with **yes** under **Asks first** change nothing until the person has agreed. If the client supports elicitation, the server asks the person directly. Otherwise the call has to be repeated with `confirm: true`. Money is never moved by a tool: billing tools return a link the person opens in the browser.

## AI connections

| Tool | Arguments | What it does | Needs | Asks first |
|---|---|---|---|---|
| `mcp_connection_revoke` | `connection`, `confirm` (optional) | Disconnects one AI app that signed in to the account (OAuth sign-in): its next call is refused, and it works again only after the person connects it anew with a sign-in. Use this for an app that connected by signing in; for an API key use mcp_key_revoke. Call mcp_connections_list first to find it. | `mcp_connections_list` | none | Lists the AI apps connected to this account by signing in, with when each connected and was last used, and the account's API keys by name and prefix (never the key itself), as the AI tools page lists them, plus serverUrl (the address an assistant connects to) and maxKeys. Use this for API keys; for an AI app that connected by signing in use mcp_connection_revoke. The key itself is never shown; pick it from the keys in mcp_connections_list. Revoking the key this chat uses ends this connection. A new key is made on the AI tools page of the dashboard. | deploy | yes |

## Errors

A refused call comes back as a tool error with a sentence meant to be read out, for example "There is no app called "shop". The apps here are: Blog, Notes." or "This key has changed something 20 times in the last minute, the most it may. Wait a moment and try again. (42 s)". Plan limits are reported the same way as in the dashboard.
